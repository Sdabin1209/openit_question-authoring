# ADR 0031: 저작 화면은 이 영역이 정적 파일로 낸다 (판정은 읽기만)

## 상태
채택(2026-11-04, 헤드 지시 구조 점검 S21, 계약 3.4.7).

## 맥락
저작 API(AuthoringRequests·AuthoringResponses·SignalsResponse)를 부르는 사람 화면이 없었다. 범위: 문진표 초안 작성·자료 올리기·검수 제출·검수 결정·신호 보기, 그리고 문진표 버전마다 release-gate 판정 상태(notice-346 3번). 사람 인증은 platform 공개 입구가 하고 화면은 `HumanAuthEndpoints` 의 값만 쓴다.

## 결정
- 이 서비스가 `/ui/` 아래 정적 파일 셋(index.html, app.js, app.css)을 `GET` 으로 준다(`Exposure` 경로 `/ui/`, `/ui/*`, `auth.kind=authenticated`: 데이터가 없는 화면이라 가입 승인 대기 계정에도 열린다, CONVENTIONS 6절). 데이터는 같은 출처의 저작 API 로만 가져온다.
- 판정 조회: `GET /v1/set-versions`(QuestionSetVersions)와 `GET /v1/set-decisions`(Decisions = release-gate I4 `find_decisions` 의 GateDecision 그대로). 읽기만 한다. 후보 제출·활성화·승인 경로를 부르는 코드는 없다(시험이 확인).
- 보안: 서버 값은 `textContent` 로만 넣는다(마크업 삽입 API 없음, 시험이 확인). 응답에 `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'`(OWASP Secure Headers; 앱이 정했으므로 공개 입구가 덮어쓰지 않는다, R2.1). 로그인 경로는 `/oauth2/start?rd=`, 로그아웃은 `/oauth2/sign_out`.
- 본문 상한: 자료 올리기 `max_body_bytes` 8 MiB(Exposure 선언) = 서버 `MAX_BODY`(ADR 0023). 측정한 값이 아니라 정상 양식(수십 KiB)의 수백 배 여유(ADR 0004의 입력 한도와 같은 취지)이며 시험이 두 값의 일치를 본다.
- `QA_GATE_URL` 이 비면 판정 조회는 412 `FAILED_PRECONDITION` 이다. 응답 스키마에 DISABLED 모양이 없어 빈 목록을 지어내지 않는다.

## 왜
- 프레임워크·빌드 도구를 쓰지 않는 이유: 화면이 다섯 개이고 번들러가 없으면 공급망·빌드 의존이 늘지 않는다. 대안 비교(React 등)는 하지 않았다(측정 안 함, 판단).
- 이 서비스가 서빙하는 이유: 영역 안 컴포넌트를 늘리지 않고 화면과 API 의 버전이 같은 이미지로 움직인다.

## 검토한 대안과 버리는 이유
- admin-console 에 저작 탭: 계약이 저작 화면을 이 영역 소관으로 정했다(S21).
- 서버 렌더링 템플릿: 템플릿 엔진 의존이 늘고 마크업 삽입 위험이 커진다.

## 결과
얻는 것: 저자가 실제로 쓸 수 있는 화면. 감수하는 것: 브라우저에서 실제로 눌러 본 시험은 하지 못했다(이 세션에는 브라우저가 없다). 정적 파일 제공, 문법(node --check), API 경로 일치, 마크업 삽입 금지, 계약 로그인 경로 사용만 자동 시험으로 확인했다.

## 되돌리는 조건
platform 이 화면 호스팅을 정하면 파일만 옮기고 API 는 그대로 둔다.
