# ADR 0026: 2인 승인(QA_REQUIRE_TWO_PERSON) 기본값을 끈다 (L13)

## 상태
채택(2026-11-03, 사용자 결정 L13). [ADR 0006](0006-임상-승인은-저자와-다른-검수자-4-eyes.md)(D92)의 설정 기본값만 대체한다. 4-eyes 동작 자체는 유지한다.

## 맥락
ADR 0006은 `QA_REQUIRE_TWO_PERSON`을 기본 true로 했다. 그 뒤 구조 잠금(U81)이 정해졌다: 문항 ID·칸 ID 구조는 학습 데이터에 고정되고 저자가 바꿀 수 있는 것은 문장과 수치뿐이다.

## 결정
기본값을 false로 한다(코드 `__main__.py`, `AuthoringService`의 기본 인자, 계약 `QuestionAuthoringEnv`의 기본). 끄면 저자 확인이 `clinical_basis_approved=true`인 검수 기록이 되고(D30 동작), `/readyz`는 `warnings: ["two_person_disabled"]`를 계속 낸다. 켜려면 `QA_REQUIRE_TWO_PERSON=true`를 준다.

## 왜
- 사용자 결정(L13). 저자가 바꾸는 것이 문장뿐이고 구조는 잠겨 있으므로 임상 구조에 닿는 변경이 열려 있지 않다고 판단했다. 이 근거는 사용자 결정이며 이 영역이 위험을 따로 측정하지 않았다.
- 현장에 검수자 계정이 없으면 기본이 켜져 있을 때 `reviewed_only` 버전이 생기지 않아 흐름이 멈춘다(ADR 0006이 이미 적은 감수 비용).

## 검토한 대안과 버리는 이유
- 기본 true 유지: 위 멈춤 비용을 계속 진다. 사용자가 끄기로 했다.
- 설정을 없애고 4-eyes 동작 삭제: 검수자를 두는 현장이 켤 수 없게 된다. 버린다.

## 결과
얻는 것: 검수자 없이도 저자 확인만으로 `reviewed_only` 버전이 생긴다. 감수하는 것: 한 사람이 올리고 확인하면 임상 승인이 되는 구조(ADR 0006이 지적한 위험)가 기본이 된다. 경고는 `/readyz`에 남는다. 이웃이 보는 변화: `reviewed_only`에 버전이 나타나는 시점이 저자 확인 직후다.

## 되돌리는 조건
구조 잠금이 풀려 문항 구조를 저자가 바꿀 수 있게 되거나, 사용자가 업무 분리를 다시 요구하면 기본을 true로 되돌리는 새 ADR을 쓴다.
