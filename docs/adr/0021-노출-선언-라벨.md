# ADR 0021: 노출 선언 deploy-exposure.json과 라벨 io.openit.exposure

- 상태: 채택 (2026-10-30, U47)

## 맥락
deploy의 `config/Caddyfile`이 이 영역의 API 경로·메서드·역할을 직접 알았다(구조 규칙 1 위반, OPEN_GAPS U47). 계약 `Exposure` 스키마와 이미지 라벨 `io.openit.exposure`(ImageLabels)가 영역의 선언을 받는다.

## 결정
정본은 리포의 `deploy-exposure.json`(계약 `Exposure`)이다. `scripts/build-image.sh`가 그 내용을 compact JSON으로 이미지 라벨 `io.openit.exposure`에 달고, 파일이 없으면 실패한다. 시험(`tests/test_exposure_u47.py`)이 (1) 파일이 계약을 통과하고 (2) 선언한 메서드·경로를 코드가 서비스하고 (3) 선언하지 않은 메서드는 코드가 서비스하지 않고 (4) 코드가 서비스하는 모든 `/v1/` 경로 묶음이 노출 또는 거부로 선언돼 있고 (5) 라벨이 파일과 같음을 본다.

## 내용과 근거
- 저자 경로(`POST /v1/materials`, `POST /v1/reviews`, `GET·POST /v1/drafts`, `/v1/drafts/*`): 계정 인증(account), 역할 `author`, `clinical-reviewer`, 서비스 토큰 비밀 이름 `qa-gateway-token`, 계정 ID를 `X-Openit-User`로 붙임, 연결 2초·응답 헤더 15초. 출처: 현재 `deploy/config/Caddyfile`의 `qa_proxy` 블록과 `@qaauthor` 경로(이 영역의 읽기 전용 확인). 시간 값은 Caddyfile의 시작값(측정 근거 없음)을 옮긴 것이다.
- 거부(denied): `/v1/question-sets*`(I1 읽기 면, 이웃 서비스 전용)와 `/v1/signals`(코드는 서비스하지만 게이트웨이는 열지 않는다).

## 어긋남 (코드가 정본, 보고함)
- Caddyfile `@qaauthor`는 메서드를 가리지 않고 경로만 연다. 코드는 `/v1/materials`·`/v1/reviews`는 POST만, `/v1/drafts*`는 GET·POST만 서비스한다. 선언은 코드를 따른다.
- 게이트웨이 역할 이름은 `author`이고 서비스 안의 역할 이름은 `question-author`다(`QA_USER_ROLES`가 잇는다). 선언의 `roles`는 게이트웨이 역할이다.
- `/v1/signals`는 Caddyfile에 없어 기본으로 404가 된다. 선언은 `denied`로 같다. 저자 화면이 개선 신호를 보려면 게이트웨이와 선언을 함께 바꿔야 한다(결정 아님).

## 검토한 대안과 버리는 이유
- 라벨을 Dockerfile `ARG`로 받음: JSON 인용이 취약하고 빌드 인자 이름을 다시 알려야 한다.
- 선언 없이 deploy가 라우트를 읽음: 구조 규칙 1 위반.
