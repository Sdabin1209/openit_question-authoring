# ADR 0013: 토큰 비교는 모든 후보를 hmac.compare_digest로 끝까지 비교

- 상태: 채택(2026-10-29, 표준성 점검 결정표 2절). ADR 0010의 "토큰 비교는 dict 조회" 부분을 대체한다(Supersedes: ADR 0010 중 해당 문단)
- 날짜: 2026-10-29

## 맥락
ADR 0010은 토큰을 dict 조회로 비교하고 "외부에 노출되지 않아 고치지 않는다"고 했다. 표준성 점검(#12)은 상수 시간 비교가 일반 권고인데 따르지 않는다고 지적했다.

## 결정
정적 토큰 표, gateway 토큰 집합, 읽기 토큰 표의 조회는 `http_api._lookup/_has`를 거친다. 표의 모든 항목을 `hmac.compare_digest`(바이트)로 비교하고 맞아도 멈추지 않는다.

## 왜 (따른 표준과 근거)
- Python `hmac.compare_digest` 문서는 타이밍 공격을 막으려는 상수 시간 비교로 소개한다. OWASP도 비밀 비교에 상수 시간 비교를 권한다(원문 대조는 하지 않았다, 기억 기준).
- 조기 종료가 없어야 후보 수에만 비례하는 시간이 된다. 정적·gateway 표를 둘 다 비교해 어느 표에서 맞았는지가 시간에 드러나지 않게 했다.
- 바이트로 비교하는 이유: `compare_digest`는 ASCII가 아닌 str에 TypeError를 낸다.

## 검토한 대안과 버리는 이유
- 토큰을 해시해 저장하고 해시를 dict 조회: 비밀 파일 형식 변경이 필요하다. 이번 범위 밖.
- 현행 dict 조회 유지: 위 표준을 따르지 않는다.

## 결과
얻는 것: 표준 권고 준수. 감수하는 것: 조회가 후보 수에 선형이다(토큰은 소수라 영향은 측정하지 않았다). 파이썬 수준 루프라 완전한 상수 시간 보증은 아니다(후보 수와 길이는 새어 나갈 수 있다).

## 되돌리는 조건
토큰이 수천 개로 늘면 해시 저장 방식으로 바꾼다.
