# ADR 0029: 데이터베이스는 이 영역의 컴포넌트다 (엔진·버전·접속 대기·백업)

## 상태
채택(2026-11-04, 헤드 지시 코드 단계, 계약 3.4.4 CONVENTIONS 13절·RUNTIME R10.1). ADR 0001(저장소 종류)을 보강하고 대체하지 않는다.

## 맥락
계약은 데이터베이스를 platform 이 주는 서버가 아니라 데이터를 저장하는 영역의 컴포넌트로 정했다(Database per Service). 엔진·버전·접속 설정·백업은 영역이 정하고 ADR 에 근거를 적는다. 다른 영역의 DB 계정·접속은 없다(이 영역은 처음부터 없다: 이웃은 I1 로만 읽는다).

## 결정
- 엔진: PostgreSQL. 버전은 배포가 고르는 공식 `postgres:16` 이미지(스모크와 개발 PostgreSQL 이 같은 16). 이 영역 코드는 psycopg 3 + 표준 SQL 이라 서버 마이너 버전에 묶이지 않는다. SQLite 는 개발·시험 전용이고 운영 구성(`QA_DATABASE_URL` 없음)이면 기동을 거부한다(ADR 0001, `QA_DEV_MODE`).
- 접속 설정: 접속 문자열은 비밀 파일 `QA_DATABASE_URL_FILE`(D84)이고, 코드는 libpq 파라미터(`sslmode`, `sslrootcert` 등)를 덮어쓰지 않는다(tests/test_tls_outbound.py). 접속 대기 `QA_DB_CONNECT_TIMEOUT_SECONDS`(기본 3초)·문장 `QA_DB_STATEMENT_TIMEOUT_SECONDS`(기본 3초)·큰 문장 30초·`/readyz` 확인 2초: 값의 근거는 ADR 0007(측정하지 않은 시작값).
- 끊긴 연결: 요청마다 연결 오류를 감지하면 새로 맺는다(RUNTIME R4.1, tests/test_postgres_specific.py::test_reconnects_after_connection_loss).
- 백업: 영역이 자기 데이터를 꺼내 자기 영역 게이트웨이 출구로 platform 백업 저장소에 보낸다(ADR 0030).

## 왜
- 표준: Database per Service(마이크로서비스 패턴), 12-Factor IV(백엔드 서비스는 붙였다 뗄 수 있는 자원, URL 설정). 접속 정보는 비밀이라 파일(D84).
- 엔진을 바꾸지 않은 이유: 변경할 필요가 없다. 이 영역의 쓰기 직렬화는 PostgreSQL advisory lock(ADR 0001)에 기대고 있어 엔진 교체는 이득 없이 위험만 크다.
- 버전을 16 으로 적은 이유: 시험과 스모크가 16 으로 돌았다. 다른 버전과의 비교는 하지 않았다(측정 안 함).

## 검토한 대안과 버리는 이유
- platform 이 주는 공유 PostgreSQL 서버: 계약이 영역 컴포넌트로 정했다.
- 영역 안에 SQLite 파일 유지: 동시 쓰기·백업·접근 제어가 약하다(ADR 0001).

## 결과
얻는 것: 데이터의 주인과 저장소의 주인이 같다. 감수하는 것: 영역이 DB 컨테이너 설정·복구 시험을 책임진다(배치는 deploy). 이 PC 에서는 일회용 컨테이너로만 확인했고 운영 서버 용량·보존은 측정하지 않았다.

## 되돌리는 조건
계약이 데이터베이스의 주인을 다시 platform 으로 옮기면 새 ADR 로 대체한다.
