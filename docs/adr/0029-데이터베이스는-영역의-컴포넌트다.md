# ADR 0029: 데이터베이스는 이 영역의 컴포넌트다 (엔진·버전·접속 대기·백업)

## 상태
채택(2026-11-04, 헤드 지시 코드 단계, 계약 3.4.4 CONVENTIONS 13절·RUNTIME R10.1). ADR 0001(저장소 종류)을 보강하고 대체하지 않는다. 일부 대체됨: 맨 아래 "2026-11-06 배포 권한 회귀 수정" 절(gosu, 비밀 사본, 배포 capability)은 [ADR 0032](0032-DB-이미지는-비-root로-실행한다.md)가 대체한다(2026-11-08).

## 맥락
계약은 데이터베이스를 platform 이 주는 서버가 아니라 데이터를 저장하는 영역의 컴포넌트로 정했다(Database per Service). 엔진·버전·접속 설정·백업은 영역이 정하고 ADR 에 근거를 적는다. 다른 영역의 DB 계정·접속은 없다(이 영역은 처음부터 없다: 이웃은 I1 로만 읽는다).

## 결정
- 엔진: PostgreSQL. 버전은 배포가 고르는 공식 `postgres:16` 이미지(스모크와 개발 PostgreSQL 이 같은 16). 이 영역 코드는 psycopg 3 + 표준 SQL 이라 서버 마이너 버전에 묶이지 않는다. SQLite 는 개발·시험 전용이고 운영 구성(`QA_DATABASE_URL` 없음)이면 기동을 거부한다(ADR 0001, `QA_DEV_MODE`).
- 접속 설정: 접속 문자열은 비밀 파일 `QA_DATABASE_URL_FILE`(D84)이고, 코드는 libpq 파라미터(`sslmode`, `sslrootcert` 등)를 덮어쓰지 않는다(tests/test_tls_outbound.py). 접속 대기 `QA_DB_CONNECT_TIMEOUT_SECONDS`(기본 3초)·문장 `QA_DB_STATEMENT_TIMEOUT_SECONDS`(기본 3초)·큰 문장 30초·`/readyz` 확인 2초: 값의 근거는 ADR 0007(측정하지 않은 시작값).
- 끊긴 연결: 요청마다 연결 오류를 감지하면 새로 맺는다(RUNTIME R4.1, tests/test_postgres_specific.py::test_reconnects_after_connection_loss).
- 백업: 영역이 자기 데이터를 꺼내 자기 영역 게이트웨이 출구로 platform 백업 저장소에 보낸다(ADR 0030).

## 영역 DB 이미지 `question-authoring-db` (계약 3.4.10·3.4.11, D126)
- `postgres:16` 위에 이미지 안 초기화를 얹는다(`db/`): 공식 이미지의 initdb 훅(`/docker-entrypoint-initdb.d`)이 첫 기동 때 한 번 선언대로 계정·데이터베이스·권한을 만든다. 선언 `db/database.json` = 라벨 `io.openit.database`(빌드가 계약 `DatabaseDeclaration` 과 이 영역 Env 스키마의 `url_env` 이름으로 검증, 실패하면 빌드하지 않는다).
- 입력은 `AreaDatabaseEnv` 뿐: `POSTGRES_PASSWORD_FILE`(슈퍼유저, 초기화에만), `DB_ACCOUNT_SECRETS_DIR`(계정마다 파일, 기본 /run/secrets/db), `DB_TLS_DIR`(tls.crt·tls.key, 기본 /certs).
- 계정: `LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION`, 암호 scram-sha-256. owner 는 자기 데이터베이스를 소유한다. dml 은 CONNECT·스키마 USAGE·SELECT/INSERT/UPDATE/DELETE·시퀀스 USAGE/SELECT 와 owner 가 만드는 새 표·시퀀스에 대한 기본 권한만. 모든 데이터베이스에서 PUBLIC 의 CONNECT 와 public 스키마 권한을 회수한다.
- 접속 규칙(`db/pg_hba.conf`, 이미지 고정): 루프백 trust 없음, 평문 접속 거절, 슈퍼유저 네트워크 접속 거절, 앱 계정은 `hostssl` + scram-sha-256. 서버 TLS 필수: 인증서가 없으면 시작하지 않는다(접속은 verify-full).
- 인증서 갱신: 진입점이 60초마다 `DB_TLS_DIR` 의 지문을 보고 바뀌면 서버 사용자 소유로 다시 복사(rename)한 뒤 postmaster 에 SIGHUP 을 보낸다(재시작 없음; ssl_cert_file·ssl_key_file 은 reload 로 적용, PostgreSQL 문서). 60초는 갱신이 만료보다 훨씬 앞선다는 전제의 시작값이다(측정하지 않음). 시험은 믿지 않는 루트의 인증서 → 믿는 루트의 인증서로 파일을 바꾼 뒤 접속이 되는 것을 본다(변이: SIGHUP 을 빼면 실패).
- 연결 상한: 서버 `max_connections=50`, 역할별 owner 40·dml 8. 근거: 서비스 동시 요청 기본 32 + 정리·백업 잡 + 관리 여유. 측정하지 않은 시작값이다.
- 제품 선언은 owner 계정 하나(`QA_DATABASE_URL_FILE`)다. 서비스가 기동 때 마이그레이션(DDL)을 하기 때문이다. 백업·정리 잡의 최소 권한(dml) 계정 분리는 맞는 방향이나 새 기능이라 헤드 대장(OPEN_GAPS)으로 넘겼다(Env 에 이름이 없다). 이미지의 dml 경로는 시험 안의 별도 선언으로 확인한다(`tests/test_database_image.py`).
- 확인하지 못한 것: 계정 암호 교체(첫 기동 때만 만든다), 이전 데이터 디렉터리를 가진 DB 의 업그레이드, 실제 deploy 배치.

## 왜
- 표준: Database per Service(마이크로서비스 패턴), 12-Factor IV(백엔드 서비스는 붙였다 뗄 수 있는 자원, URL 설정). 접속 정보는 비밀이라 파일(D84).
- 엔진을 바꾸지 않은 이유: 변경할 필요가 없다. 이 영역의 쓰기 직렬화는 PostgreSQL advisory lock(ADR 0001)에 기대고 있어 엔진 교체는 이득 없이 위험만 크다.
- 버전을 16 으로 적은 이유: 시험과 스모크가 16 으로 돌았다. 다른 버전과의 비교는 하지 않았다(측정 안 함).

## 검토한 대안과 버리는 이유
- platform 이 주는 공유 PostgreSQL 서버: 계약이 영역 컴포넌트로 정했다.
- 영역 안에 SQLite 파일 유지: 동시 쓰기·백업·접근 제어가 약하다(ADR 0001).

## 결과
얻는 것: 데이터의 주인과 저장소의 주인이 같다. 감수하는 것: 영역이 DB 컨테이너 설정·복구 시험을 책임진다(배치는 deploy). 이 PC 에서는 일회용 컨테이너로만 확인했고 운영 서버 용량·보존은 측정하지 않았다.

## 되돌리는 조건
계약이 데이터베이스의 주인을 다시 platform 으로 옮기면 새 ADR 로 대체한다.

## 추가: DB 이미지 HEALTHCHECK

- 결정: 이미지에 Dockerfile `HEALTHCHECK`(`db/healthcheck.sh`)를 둔다. 건강 = 선언(`/etc/openit/database.json`)한 계정마다 역할이 있고 LOGIN 가능하며 선언한 데이터베이스에 CONNECT 할 수 있고(소켓 peer, 암호 불필요), 서버가 TLS 로 접속을 받는다(암호 없이 `sslmode=require` 로 붙어 "no password supplied" 가 오면 TLS 핸드셰이크가 끝난 것).
- 왜: `pg_isready` 는 서버가 연결을 받는지만 보고 TLS 와 계정을 보지 않는다. Docker 표준 HEALTHCHECK 로 이미지가 스스로 확인한다. 구조 규칙 1: 점검은 자기 선언만 읽는다. 계정 암호는 점검에 들이지 않는다(D84).
- 값: interval 15s(앱 이미지와 같음), timeout 5s(점검 안 timeout 4s 보다 큼), start-period 60s, retries 3. 모두 측정하지 않은 시작값이다.
- 확인: `tests/test_database_image.py` 의 변이 시험 — `-c ssl=off` 로 뜬 서버는 pg_isready 는 통과하지만 unhealthy, 선언 계정이 LOGIN 을 잃으면 unhealthy, TLS 파일이 없으면 컨테이너가 시작하지 않아 healthy 가 될 수 없다.
- 되돌리는 조건: 점검이 부하 때 오탐으로 컨테이너를 재시작시키면 retries·timeout 을 측정해 다시 정한다.


## 2026-11-06 배포 권한 회귀 수정 (대체됨: ADR 0032)

아래는 당시 기록이며 현재 동작이 아니다. 현재는 이미지가 처음부터 postgres(999:999)로 실행되어 gosu·비밀 사본·capability 가 없다.

기존 AreaDatabaseEnv의 DB_ACCOUNT_SECRETS_DIR에서 계정 비밀을 읽어 /run/question-authoring-db-secrets(postgres 소유 0700, 파일 0600)에 준비한 뒤 공식 진입점으로 넘긴다. gosu의 사용자 전환 후에도 배치 비밀 0640을 완화하지 않고 읽게 하기 위함이다. 읽기 실패·빈 첫 줄은 초기화 전에 거부한다. TLS 갱신 신호는 gosu postgres kill로 보내 CAP_KILL 없이 동작한다. DB 이미지 시험은 읽기 전용 루트·배포 capability·0640 비밀로 실행한다.
