# ADR 0018: 작성 양식의 칸 규격 줄 문법

- 상태: 채택 (2026-10-30, D115 U32)
- 날짜: 2026-10-30

## 맥락
문진 스키마 survey-schema-v1.2.0이 `SlotDef`에 선택 속성 5개(`data_type`, `unit`, `minimum`, `maximum`, `exclusive_minimum`)를 더했다. survey-service는 문항 은행의 이 값으로 계약 QuestionFieldSpec(v2.4.1)을 만들어 LoRA-A에 보낸다. 문항 은행은 이 영역이 만들므로 작성 양식이 이 값을 받아야 한다.

## 결정
슬롯 아래에 줄 5종을 둔다: `자료형: boolean|integer|number|option`, `값 단위: <이름>`, `최소: <수>`, `최대: <수>`, `초과 최소: <수>`. 모두 선택이다. 줄이 없으면 SlotDef에 키를 넣지 않는다(이전 문항 은행과 같다).

## 왜
- 기존 줄과 같은 `키: 값` 모양이라 추출기의 규칙(첫 콜론 분할, 정해진 모양에만 값으로 읽음, 아니면 UNSURE)을 그대로 쓴다(ADR 0004).
- `단위:` 줄은 이미 UnitDef(사용자 말의 단위, 같은 말, 범위, 환산)다. SlotDef.unit은 다른 뜻(칸 값의 단위 이름)이라 `값 단위`로 이름을 갈랐다. `범위 최소 ~ 최대`는 UnitDef.range라 칸 규격의 최소·최대와 겹치지 않는다.
- 자료형 열거와 속성 이름은 문진 스키마가 정본이고(survey-service 소유) 이 영역은 사본의 값 집합만 읽는다. 열거를 어기면 문항 은행 검증이 거부하므로 추출 단계에서 먼저 UNSURE로 알린다.
- 값 자체(어느 칸이 0~7인지)는 임상·데이터셋의 몫이다. 이 영역은 모양만 읽는다(D30).

## 검토한 대안과 버리는 이유
- `단위:` 줄에 `자료형` 등을 하위 항목으로 붙임: UnitDef는 단위가 여러 개일 수 있어 칸에 하나인 값과 맞지 않는다.
- 한 줄 `칸 규격: integer | day/week | 0 ~ 7`: 위치 의존이라 일부만 쓰기 어렵고, 틀린 항목만 UNSURE로 가리기 어렵다.

## 결과
- 얻는 것: 양식 작성자가 값을 쓰면 문항 은행 SlotDef와 QuestionFieldSpec으로 이어진다. 읽지 못한 값은 비워 두고 미리보기에서 눈에 띈다.
- 감수하는 것: 최소와 최대의 앞뒤 순서 검사는 줄 순서에 의존해 한쪽만 먼저 있으면 서로 비교하지 않는다(문항 은행 검증이 아니라 저자 확인으로 남는다). 변경 분류는 이 5개를 `선택지·단위`, 임상 검토 필요로 본다(근거: 값 범위와 단위를 정하는 임상 수치이기 때문, 다른 분류와 비교 측정은 안 함).

## 되돌리는 조건
문진 스키마가 속성 이름을 바꾸거나 QuestionFieldSpec이 선택지·반복 키까지 양식에서 받아야 하면 새 ADR로 대체한다(선택지 `options`·`repeat_keys`는 survey-service가 `choices`/`repeat_keys`에서 만든다고 보고 이 ADR에서 다루지 않았다. 확인한 것은 아님).
