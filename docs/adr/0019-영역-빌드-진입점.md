# ADR 0019: 영역 빌드 진입점 scripts/build-image.sh

- 상태: 채택 (2026-10-30, U42)
- 날짜: 2026-10-30

## 맥락
deploy의 `build-images.sh`가 이 영역의 Dockerfile 인자 이름(`COMMIT`, `BOUNDARY_TAG`, `SURVEY_SCHEMA_TAG`)과 빌드 산출 파일(`build/contracts.tag`, `build/survey-schema.tag`)을 직접 알았다. 구조 규칙 1(영역은 서로의 구조를 모른다) 위반이다(U23 감사, OPEN_GAPS U42). 계약 boundary-contracts 2.5.0이 영역 빌드 진입점(`BuildImageRequest`/`BuildImageResult`)을 확정했다.

## 결정
`bash scripts/build-image.sh <요청 JSON>`이 진입점이다. 인자 이름, 빌드 컨텍스트, 라벨 값 만들기는 이 영역 안에서만 안다.
1. 요청을 계약 `BuildImageRequest`로 검증한다(`scripts/_build_request.py`, 영역 경계 입력). 이 영역이 쓰는 키(`versions.survey_schema`, `dependency_sources.boundary`, `dependency_sources.survey_schema`)가 없으면 기본값 없이 실패한다. `variant`는 이미지가 하나라 거부한다. `turn_engine`은 폐기라 받기만 한다.
2. 빌드 컨텍스트는 `source_dir`의 소스(`.git`, `.venv`, `build` 제외)를 임시 폴더에 복사한 것이다. `source_dir`은 고치지 않는다. 라이브러리 wheel은 `dependency_sources`를 복사해 만든다(이웃 리포 경로·빌드 중 SSH 없음).
3. 결과는 표준 출력 마지막 줄 한 줄이다: `image_id`는 docker가 준 값, `labels`는 이미지에서 읽은 `io.openit.*`(요청 값을 되풀이하지 않는다).

## 왜 (근거)
- 구조 규칙 1과 계약 2.5.0: deploy는 요청 한 장으로 영역을 빌드하고 결과 라벨로 버전 일치를 검사한다. 영역의 파일은 읽지 않는다.
- 요청 검증을 계약 validator로 하는 이유: 셸에서 JSON을 파싱하면 계약과 어긋난다(R7: 경계 입력은 계약이 정본). Python 해석기는 `PYTHON`(없으면 `python3`)이고 `boundary-contracts`(2.5 이상)와 `jsonschema`가 있어야 한다.
- 문진 스키마 라벨은 주 버전 정수다: 계약 `ImageLabels`가 `survey-schema`를 `^([0-9]+|n/a)$`로 정한다. 요청의 `survey_schema`는 `vX.Y.Z`라 주 버전을 뽑는다.
- 같은 요청은 같은 이미지(멱등): wheel 안 시각과 컨텍스트 파일 시각을 소스 커밋 시각(`git show -s --format=%ct`, 없으면 0)으로 고정하고, 빌드에 `SOURCE_DATE_EPOCH`를 주며, `--provenance=false --sbom=false`로 증명 매니페스트(빌드 시각이 들어간다)를 뺀다. 확인한 것: 같은 요청으로 이미지를 지우고 세 번 다시 빌드해 `image_id`가 같았다(docker 28.5.1, containerd 이미지 저장소). `--provenance`는 BuildKit 옵션이라 그것이 없는 docker에서는 빌드가 실패한다.

## 검토한 대안과 버리는 이유
- 빌드 산출을 `source_dir/build`에 쓰기: 요청한 소스 트리를 더럽히고 읽기 전용 트리에서 실패한다.
- 요청 검증 없이 셸에서 키를 꺼냄: 모르는 키·잘못된 형식을 걸러내지 못한다.

## 결과
- 얻는 것: deploy가 이 영역의 Dockerfile 인자·산출 파일을 몰라도 된다. 시험은 가짜 `DOCKER`로 요청 검증과 결과 모양을 보고(`tests/test_build_image.py`), 실제 빌드는 `scripts/smoke.sh`가 한다.
- 감수하는 것: `scripts/build_wheels.sh`가 남아 있다(옛 deploy `build-images.sh`가 부른다, deploy가 진입점으로 바꿀 때 지운다). `scripts/smoke.sh`는 개발용으로 잠금 파일의 핀 태그에서 소스 트리를 꺼내 요청을 만든다(이웃 리포를 읽는 곳은 이 한 군데이고 배포에서는 deploy가 한다).

## 되돌리는 조건
계약의 빌드 요청 모양이 바뀌면(3.0.0 등) 새 ADR로 대체한다.
