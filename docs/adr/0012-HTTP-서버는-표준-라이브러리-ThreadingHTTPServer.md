# ADR 0012: HTTP 서버는 표준 라이브러리 ThreadingHTTPServer

- 상태: ADR 0016이 대체함(2026-10-29). 이전 상태: 채택(0.1.0), 한도 보강은 0.6.3
- 날짜: 2026-10-28

## 맥락
저작 API와 I1 읽기 면을 HTTP로 낸다. 사용자는 관리자 소수다.

## 결정
`http.server.ThreadingHTTPServer` 위에 핸들러를 얇게 두고, 로직은 `Api.handle()`(소켓 없는 순수 함수)과 `service.py`에 둔다.

## 왜 (따른 표준과 근거)
- `handle()`이 순수 함수라 소켓 없이 시험할 수 있다(http_api.py 머리 주석). 의존이 없어 이미지가 작고 잠금 파일에 올릴 것이 없다. 관리자 소수라는 가정에서 처리량 요구가 낮다.
- 대가를 안다: 스레드 수 상한·요청 크기·timeout 기본값이 없다. 그래서 동시 요청 세마포어, 소켓 timeout, 인증 전 본문 미수신, Content-Length 검증, 예상 밖 오류의 JSON 500, SIGTERM 정상 종료를 직접 넣었다(ADR 0007).
- 프레임워크(FastAPI 등)와의 비교는 하지 않았다. **근거 기록 없음(비교 측정·검토 기록이 없다)**: 위는 현재 코드의 성격에서 추정한 이유다.

## 검토한 대안과 버리는 이유
- 프레임워크/ASGI 서버: 의존이 늘고 이 규모에서 얻는 것이 불명확. 검토 기록 없음.
- 외부 WSGI 서버(gunicorn): 위와 같다.

## 결과
얻는 것: 단순함. 감수하는 것: HTTP/1.0 기본, 청크 본문 미지원(빈 자료 400), 한도를 직접 유지보수.

## 되돌리는 조건
저자 클라이언트가 gateway를 통해 늘 쓰이거나 부하가 커지면 프레임워크/성숙한 서버로 옮기고 이 ADR을 대체한다.
