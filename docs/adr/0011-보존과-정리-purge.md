# ADR 0011: 보존과 정리 purge

- 상태: 채택(D88 U4, 2026-10-28), 값은 잠정 기본값
- 날짜: 2026-10-28

## 맥락
초안과 원본 자료가 무기한 쌓였다(점검 A6, C3). 환자 정보 경고를 수락한 자료도 영구 저장됐다. 보존 기간은 병원 정책이 필요한 값이다.

## 결정
`python -m question_authoring purge`(run-once, 멱등, 스케줄은 deploy, D39). 처리되지 않은(OPEN, DISCARDED) 초안은 30일 뒤, 어떤 버전·남은 초안도 참조하지 않는 원본 자료(고아 포함)는 30일 뒤 지운다. 버전·검수·변경 분류·확정된 초안은 보존한다. 보존 일수는 설정(`QA_DRAFT_RETENTION_DAYS`, `QA_SOURCE_RETENTION_DAYS`)이고 0·음수·none(무기한)은 거부한다. 저장 시각을 모르는 기존 원본은 첫 실행 때 시각을 적고 그때부터 센다.

## 왜 (따른 표준과 근거)
- 30일: D88이 '잠정 기본값'으로 정했다. 법적 근거나 병원 정책에서 나온 값이 아니다(**근거 기록 없음, 병원 확정 필요**).
- 불변 기록은 지우지 않는다: 버전·검수는 게이트와 재현의 기반이다(ADR 0002).
- 참조 중인 원본을 지우지 않는 이유: 버전의 출처 해시가 가리키는 원본이 사라지면 출처를 확인할 수 없다.
- 삭제는 확인과 삭제를 한 문장으로 한다(2차 점검: 계산 후 삭제 사이에 새 초안·재업로드가 끼어드는 경쟁). 재업로드는 저장 시각을 갱신한다.
- run-once 잡 방식: 워크스페이스 규칙(영역은 스스로 다른 것을 깨우지 않고 deploy 스케줄러가 돌린다, D39).

## 검토한 대안과 버리는 이유
- 서비스 안 백그라운드 스레드로 정리: 스케줄·장애를 영역이 숨겨서 갖게 된다. 규칙 위반. 버림.
- 무기한 보존(기본): 점검이 M으로 지적. 버림.

## 결과
얻는 것: 저장이 무한히 늘지 않고 수락된 환자 정보 자료가 영구히 남지 않는다. 감수하는 것: 30일 넘게 작업 중인 초안은 사라진다(최근 수정이 기준이라 편집하면 연장). deploy가 purge를 스케줄하지 않으면 동작하지 않는다(미연결).

## 되돌리는 조건
병원이 보존 기간을 정하면 값을 바꾼다. 원본을 아예 저장하지 않는 옵션은 사용자 결정.
