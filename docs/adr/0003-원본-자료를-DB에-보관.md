# ADR 0003: 원본 자료를 DB에 보관

- 상태: 채택(0.1.0), 보존 기간은 0.6.3에서 추가
- 날짜: 2026-10-28

## 맥락
저자가 올린 파일의 해시가 문항 세트 버전의 출처다(brief 4절). 파싱이 틀렸을 때 원본을 다시 볼 수 있어야 하고 FALLBACK 초안에서도 원본 해시가 남아야 한다. 본문 상한은 8MiB다(ADR 0007).

## 결정
원본 바이트와 파일 이름을 `blobs` 테이블(해시가 키, 같은 자료는 한 번만)에 둔다. 해시와 크기는 ReviewRecord `ext.question-authoring.source`에 남는다. 어떤 버전·초안도 참조하지 않는 원본은 보존 기간(기본 30일) 뒤 `purge`가 지운다(ADR 0011).

## 왜 (따른 표준과 근거)
- 쓰기 원자성과 백업을 한 곳에서: 버전·초안과 같은 DB라 같은 `pg_dump`로 백업·복원되고, 파일과 DB 사이의 불일치(파일은 있는데 행이 없음)가 생기지 않는다. 컨테이너가 `read_only` + `/data` 한 볼륨이라는 deploy 구성과도 맞는다.
- 크기: 문항 자료는 텍스트 양식이라 작다(예시 양식 수 KB). 최대 8MiB를 PostgreSQL `BYTEA`에 넣는 시간을 실측했다: 0.09초 이하(일회용 PostgreSQL, 이 PC 한 환경, boundary.md). 실제 저자 자료의 크기 분포는 모른다.

## 검토한 대안과 버리는 이유
- 파일 시스템 볼륨: 별도 백업·권한·정리가 필요하고 DB 행과 어긋날 수 있다. 버림(현재 규모에서 이득이 없음).
- 객체 저장소(S3 등): 운영 의존이 하나 늘고 deploy에 없다. 자료가 수십 MB 이상으로 커지거나 수가 많아지면 후보. 지금은 버림.
- 원본을 저장하지 않고 해시만: 출처 확인과 재파싱이 불가능해진다. 환자 정보 경고를 수락한 자료를 영구 저장하는 문제는 있어 보존 기간을 둔다(ADR 0011). 개인정보 최소 수집 관점에서 '해시만' 옵션은 사용자 결정으로 남겼다(미결정).

## 결과
얻는 것: 단일 백업·트랜잭션. 감수하는 것: DB가 커진다(보존 기간으로 제한), 큰 쓰기가 연결을 오래 쥔다(큰 자료 경로 문장 상한을 따로 둠, ADR 0007).

## 되돌리는 조건
자료가 커져 DB 백업·복제가 부담되거나 자료 수가 크게 늘 때 객체 저장소로 옮긴다. `put_source/get_source`만 바꾸면 된다.
