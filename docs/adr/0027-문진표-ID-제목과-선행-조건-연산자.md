# ADR 0027: 문진표 ID·제목을 저자가 정하고 선행 조건은 6연산자로 읽는다

## 상태
채택(2026-11-03, 헤드 지시 WO-320, 사용자 결정 "문진표 여러 개가 함께 활성"). 문진 스키마 4.0.0과 계약 3.3.0에 맞춘다.

## 맥락
문진표(문항 세트)가 여럿 활성이고 세션마다 고른다. 문진 스키마 4.0.0은 `QuestionBank`에 `question_set_id`, `title`을 필수로 두고 `Prerequisite`를 `{slot, op, value}`(op 6종, value 문자열|수|bool)로 바꿨다. 순서·건너뛰기는 문항의 `order`, `prerequisite`에서 나온다. 텍스트 양식은 둘 다 표현하지 못했다.

## 결정
- 양식 머리에 `문진표 ID: `, `문진표 제목: `를 둔다. 둘 다 필수다. 추출기는 없으면 MISSING 플래그, 형식이 틀리면 UNSURE를 달고 값을 비운다. `bank_validate`가 스키마(필수, ID 패턴, 제목 1자 이상)로 막아 확인되지 않게 한다.
- ID는 올린 문항 세트 ID(I1 `{id}`)와 같아야 한다. 다르면 자료 등록 때 `FAILED_PRECONDITION`으로 거절한다(`draft_ingest`). 화면 입력으로 바뀐 경우는 `bank_validate`가 같은 검사를 한다(입력 `question_set_id`).
- 선행 조건은 `<문항>.<슬롯> <연산자> <값>`, 연산자 `== != > >= < <=`. 값은 참조 칸의 종류로 변환한다: 예/아니오 칸(`yes_no_map`이 있거나 `data_type: boolean`)은 true|false, 수 칸(`data_type`이 integer|number이거나 `units`가 있음)은 수, 그 밖은 문자열. 읽은 뒤에 칸 종류를 알 수 있으므로 변환은 문서 끝에서 한다. 변환하지 못하면 추정하지 않고 UNSURE로 알린다. `bank_validate`는 값 종류와 칸 종류의 일치, 순서 연산자는 수 칸에만, 칸 존재를 검사한다.
- 옛 `=` 형식은 읽지 않는다(UNSURE). 모호한 호환 읽기를 두지 않는다.

## 왜
- 표준: 스키마가 정본이고(구조 규칙, 값의 모양은 survey-schema 4.0.0 `Prerequisite`) 양식은 그것을 읽는 입구일 뿐이다. 칸 종류로 값을 정하는 것은 스키마 설명("bool과 수는 다른 값이다")을 따른 것이다.
- ID를 양식에서 읽고 올린 ID와 맞추는 이유: 다른 문진표 자료가 이 세트의 새 버전이 되는 사고를 막는다. 대안(올린 ID를 bank에 넣어 줌)은 저자가 ID를 눈으로 확인하지 못해 버렸다.
- `slot_kind` 판정이 추출기와 `bank_validate`에 두 번 있는 것은 컴포넌트끼리 import하지 못해서다(구조 규칙 3). 같은지는 시험이 본다.

## 검토한 대안과 버리는 이유
- 칸 종류를 값의 모양으로 추측(true면 bool): `yes_no`가 아닌 문자열 칸의 `true`가 bool이 된다. 버린다.
- 변환 실패 때 문자열로 두기: 스키마는 통과하지만 런타임 비교가 영영 거짓이 된다. 버린다.

## 결과
얻는 것: 문진표가 ID·제목·건너뛰기를 자기 안에 담는다. 감수하는 것: 기존 양식(ID·제목 없음)은 다시 올릴 수 없고 헤더를 추가해야 한다. 옛 `=` 선행 조건도 고쳐야 한다. 구조 잠금은 그대로라서 둘째 버전부터 문항·칸 ID 구조는 기반과 같아야 한다.

## 되돌리는 조건
문진 스키마가 `Prerequisite`나 `QuestionBank`의 필수 항목을 바꾸면 새 ADR로 대체한다.
